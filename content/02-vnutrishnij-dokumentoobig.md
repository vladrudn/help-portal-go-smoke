Цей розділ пояснює, як створити **внутрішній** документ у СЕДО: рапорт або доповідну на командира / НШ, службовий лист між підрозділами, запит на довідку чи витяг.

Назву у Word (наприклад, «ДОПОВІДНА ЗАПИСКА») можна лишити як є. У картці СЕДО важливий саме **вид документа** в полі РКК.

:::callout{type="info" title="Який вид обрати в РКК"}
- **«Внутрішня»** — рапорт або доповідна **на командира** або **начальника штабу** (у тому числі ТВО НШ).
- **«Службовий лист»** — звернення до начальників служб / груп / відділень або обмін між підрозділами без схеми «кінцевий розгляд тільки через оператора».
- Відповідь на внутрішнє звернення часто оформлюють як **«Документи УД»** (витяги, акти, довідки тощо) через кнопку «Відповісти» з вхідної картки.
:::

## Крок 1. Створити проєкт

1. Відкрийте **Картотека → Проєкти → Внутрішні**.
2. Натисніть **«+»** / **«Новий запис»**.
3. Відкриється нова РКК проєкту.

![Картотека → Проєкти → Внутрішні та кнопка «Новий запис»](/images/sections/a2001297-37bd-4a6a-a02b-b91835111543.png)
## Крок 2. Заповнити вкладку «Інформація»

Заповніть обов’язкові поля. Неповна картка — типова причина повернення на доопрацювання.

1. **Гриф** — лише **«Відкрита інформація»** (у відкритій зоні СЕДО).
2. **Вид документа** — **«Внутрішня»** або **«Службовий лист»** (див. підказку вище).
3. **Тематика** і **Класифікація** — за змістом (для рапорту часто класифікація «Рапорт»).
4. **Підписав** — хто відповідає за зміст і підписує документ.
5. **Підготував** — користувач із чинним ключем СЕДО; якщо ключа немає, залиште поле порожнім і внесіть ПІБ, посаду, підрозділ і телефон у **«Примітки»**.
6. **Дата документа** — у полі РКК (для рапорту — дата підпису), а не як «намальований» реєстраційний реквізит у Word.
7. **Короткий зміст** — стисло й зрозуміло. Наприклад: «Допущення до ТВО Іванова А.П.»
8. **Арк.** / **Додатка (арк.)** — кількість аркушів основного файлу й додатків.

![Вкладка «Інформація» з обов’язковими полями](/images/sections/84466c97-4f17-4863-8ef2-67748ba21467.png)
## Крок 3. Додати файли

1. Додайте файл кнопкою зі скріпкою або просто перетягніть файл мишкою в блок **«Файли»**.
2. Для **головного файлу** (рапорт, доповідна; для вихідної — супровідний лист) використовуйте **PDF / DOC / DOCX / XLS** (та інші підтримувані текстові формати). **PNG / JPEG** як головний файл не підходять: через них часто ламається підпис і штрих-код реєстрації. Окреме зображення-додаток — лише якщо це справді додаток, а не сам документ.
3. У файлі **проєкту** не проставляйте вручну реєстраційний номер, дату реєстрації й візуалізацію підписів — їх накладає система після реєстрації.
4. Підписані файли з **іншого ключа** не видаляйте. Якщо виправити треба **свій ще не відправлений** проєкт і підпис лише ваш — можна замінити файл і підписати знову. Якщо вже є чужі підписи або документ пішов далі по маршруту / на реєстрацію — краще додати **нову версію**.

:::callout{type="tip" title="Файл уже з підписом (наприклад, довідка з Дії)"}
Натисніть кнопку **«Приєднати файл з електронним підписом»** (скріпка з ключем). Спочатку оберіть сам файл документа, потім файл підпису **`.p7s`**.
:::

![Блок «Файли» та приєднання файлу з електронним підписом](/images/sections/cf4ba207-79ca-40ad-b97e-8388af585805.png)
## Крок 4. Підписати файл КЕП

Якщо ви самі є підписантом і подаєте документ особисто:

1. Клацніть правою кнопкою (або «три крапки») по файлу → **«Підписати»**.
2. Оберіть **апаратний носій**, центр сертифікації, носій і введіть пароль.
3. Перевірте, що біля файлу з’явилась позначка підпису.

Себе в маршруті окремо **«На підпис»** додавати зазвичай не потрібно, якщо файл уже підписано КЕП і ви зазначені в полі «Підписав». Опція «На підпис» у маршруті потрібна, коли підписує інша особа через чергу погодження (або так вимагає локальний порядок).

![Контекстне меню файлу: Підписати](/images/sections/1f361f66-719a-4da8-9365-e84b85bcd5d6.png)
## Крок 5. Налаштувати погодження

1. Відкрийте вкладку **«Погодження»**.
2. Додайте осіб з потрібними діями:
   - **Перевірка** — перевірити коректність;
   - **Погодження** — віза з КЕП;
   - **Підпис** — вирішальний підпис у маршруті;
   - **Ознайомлення** — контроль / інформування;
   - **На розгляд** — для кінцевого адресата (див. важливе правило нижче).
3. Виставте **етапи** (1, 2, 3…), щоб документ ішов по команді.
4. Поставте прапорець у колонці **«!»** лише навпроти осіб **першого** етапу. Наступні етапи система активує сама після завершення попереднього.
5. Себе на **«Ознайомлення»** додавати **не обов’язково** — статус і так видно з повідомлень після дій з документом.

:::callout{type="warning" title="Хто ставить командира або НШ на розгляд"}
Якщо це рапорт чи доповідна **на командира** або **НШ** (вид «Внутрішня»), **не додавайте** їх на «Розгляд» самостійно. Після «На реєстрацію» це зробить **оператор СЕДО**, коли потрібні погодження вже пройдені.

Якщо це **службовий лист** і кінцевий адресат — начальник служби/підрозділу, тоді особу на «Розгляд» додає **ініціатор**.
:::

![Вкладка «Погодження»](/images/sections/6074a1fd-d099-4b73-aae9-e34fe60705d5.png)
## Крок 6. Відправити на реєстрацію

1. Збережіть картку.
2. Переконайтесь, що потрібні файли підписані.
3. На вкладці **«Інформація»** натисніть **«На реєстрацію»**.
4. Далі оператор перевіряє РКК і підписи, реєструє документ і (для рапорту/доповідної на КВЧ/НШ) направляє на розгляд.

Якщо кнопки «На реєстрацію» немає з технічних причин, зверніться до оператора СЕДО частини щодо локального запасного порядку.

![Кнопка «На реєстрацію»](/images/sections/6f7ff060-6a5a-482b-874f-5e24d7f42e6b.png)
## Крок 7. Відстежити статус

- Документи на дію: **АСКОД Сьогодні → ДОКУМЕНТИ**.
- Резолюції та задачі: **АСКОД Сьогодні → РЕЗОЛЮЦІЇ / ЗАВДАННЯ**.
- Повернення на доопрацювання: виправте зауваження й натисніть **«Скасувати»** доопрацювання, коли все готово знову.

:::accordion{title="Чекліст перед «На реєстрацію»"}
- [ ] Гриф — відкрита інформація
- [ ] Вид документа обрано правильно («Внутрішня» або «Службовий лист»)
- [ ] Короткий зміст, аркуші, підписав/підготував заповнені
- [ ] Головний файл не PNG/JPEG (PDF/DOC/DOCX/XLS); орієнтація сторінок коректна
- [ ] У Word проєкту немає ручного номера/дати реєстрації та візуалізації підписів
- [ ] КЕП на потрібних файлах накладено (або файл+`.p7s` через скріпку з ключем)
- [ ] Етапи погодження логічні; прапорець «!» стоїть лише на 1-му етапі
- [ ] Для рапорту/доповідної на КВЧ/НШ їх немає у списку на «Розгляд» (це зробить оператор)
- [ ] (Опційно) себе на «Ознайомлення» — не обов’язково, статус видно з повідомлень
:::

:::accordion{title="Типові причини повернення"}
- порожні або невірні поля РКК;
- PNG/JPEG як головний файл замість PDF/DOC/DOCX/XLS;
- реєстраційні реквізити або візуалізація підписів у проєкті;
- некоректний список погодження / немає прапорця «!» на першому етапі;
- для вихідних (окремий розділ) — немає вкладки «Адресати».
:::
